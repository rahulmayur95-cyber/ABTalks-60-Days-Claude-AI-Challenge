02 How the loop governs itself

Planner turns your topic into a section outline and search queries.

Executor researches live (web search) and writes draft v1 against the outline.

Evaluator scores the current draft 1–10 on depth, evidence, clarity, structure — every round, on the newest draft only.

Critic reads the score's reasoning and names concrete gaps the Evaluator didn't fully spell out.

Improver rewrites the draft using only that round's evaluation + critique + condensed memory — never the raw history.

Memory Manager compresses what changed into a running memory note, so context doesn't balloon round over round.

Final Reviewer only activates once a stop condition fires — it never sees intermediate drafts, only the last approved one.

Each round checks, in order: plateau (score gain < 0.3 for two straight rounds) → threshold (score ≥ your target) → hard cap (safety fallback only). Whichever fires first ends the loop and is reported by name.

Architecture overview

Seven single-purpose agents share state through a plain JS object rather than a fixed script: a history array of {round, score, critique, draft, delta}, a condensed memory string rewritten each round, and the current draft. The orchestrator is a while loop with no preset length — every pass re-evaluates the newest draft live, and the three stop checks (plateau, threshold, hard cap) run in order before any Improver call is made. Each agent is a distinct system prompt against the same Claude endpoint; the Executor is the only agent given the web_search tool, since it is the only step that needs external grounding.

Extension ideas

  • Parallel drafts: run 2–3 Executors on different angles, let Evaluator pick a winner before the improvement loop starts.
  • Human-in-the-loop gate: pause after 2 rounds for a person to approve direction before continuing autonomously.
  • Tool-using Critic: give Critic web_search too, so it can fact-check claims instead of only reasoning about them.
  • Cost-aware stopping: add a 4th stop check — diminishing quality gain per token spent.
  • Multi-topic batches: queue several topics and run the whole studio unattended, exporting reports on completion.

Prompts for building more advanced autonomous systems

"Add a Safety Monitor agent that runs alongside the Critic and can veto an Improver rewrite if it introduces unsupported factual claims — show its veto in the activity log."
"Turn the plateau check into an adaptive delta that tightens as the score approaches the target, instead of a fixed 0.3 threshold."
"Give the Memory Manager its own small evaluation pass, scoring how much context it's compressing away each round, and surface that as a compression ratio stat."
"Extend this into a two-topic comparative studio where a final Synthesizer agent merges two independently-converged reports into one comparison."
