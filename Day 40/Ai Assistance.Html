Architecture & System Prompt Design (How this was built)

The "Brain" (System Prompt)

The core intelligence of this application is driven by a highly structured system prompt. By strictly defining the role, constraints, and output format, we ensure Claude generates a consistent, ready-to-render document rather than conversational chatter.

You are an elite MBB Strategy Consultant and Case Interview Designer.
Your task is to generate a comprehensive, high-quality case interview document for an MBA student preparing for consulting interviews.

CRITICAL INSTRUCTION: You MUST output ONLY raw, semantic HTML. Do not use Markdown blocks (```html). Use tags like <h1>, <h2>, <p>, <ul>, <table>.

Structure the document exactly as follows:
1. <h1> [Catchy Case Title]
2. <h2> Prompt & Context
3. <h2> Clarifying Information (to be withheld)
4. <h2> Suggested Framework (MECE structure)
5. <h2> Quantitative Exhibit & Math Problem (Include an HTML table and step-by-step solution)
6. <h2> Qualitative Brainstorming
7. <h2> Recommendation / Synthesis
8. <h2> Grading Rubric (Pass vs. Excellent)

Tailor the tone and structure strictly to the requested Firm, Case Type, Industry, and Difficulty.

UI/UX & Frontend Logic

This is a zero-dependency, single-file application. The UI is designed to mimic premium consulting materials using serif headers (Georgia) and clean sans-serif body text.

  • API Integration: Uses the native `fetch` API to call `api.anthropic.com/v1/messages`. It includes the `anthropic-dangerously-allow-browser: true` header to bypass CORS for client-side execution.
  • State Management: Transitions smoothly between Empty, Loading (Shimmer effect), Success, and Error states without page reloads.
  • Security: The API key is stored only in memory during the session (or optionally `localStorage` if expanded), and the input field acts as a password mask.

Future Extensions

To upgrade this to the "Interactive Chat Coach" (Option A from our interview), we would:

  • Change the output constraint to conversational JSON.
  • Add an array to store `message history` (Memory).
  • Build a chat UI overlay instead of a document viewer.
